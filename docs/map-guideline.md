# 부울경 지도 큰틀 가이드

작성일: 2026-11-27 / 상태: 제안 (미적용, 코드 변경 없음)

세부 사항은 바뀔 수 있어서 **변하지 않는 원칙**과 **바뀔 수 있는 부분**을 나눠 정리한다.

## 1. 목적
부울경 범위의 범용 지도. 주제는 **계단 없는 길 지도**(언덕·계단이 많은 부울경에서 경사와 계단을 피하는 보행 경로, 필요하면 태풍·침수 위험 구간 표시)로 정했다. 러닝코스와 축제는 뒤에 얹을 수 있는 레이어 후보로 남긴다. 디자인은 부드럽고 몽글몽글한 느낌을 목표로 한다.

## 1-1. 부울경 범위 (2026-11-27 기준)
- 지도 이동 제한 사각형: 경도 127.5~129.7, 위도 34.5~36.0 (남해·거창·울산 포함, 대략적인 값이며 행정경계가 아님)
- 부산 집계용 사각형: 경도 128.75~129.35, 위도 34.9~35.4 (김해·양산 일부가 섞임)
- 지도 이동 범위는 이후 **전국**(경도 124.0~132.2, 위도 32.8~38.8)으로 넓혔고, 시작 화면만 부산이다. 울산·경남·서울·제주·강원·전남·독도에서 라벨 모두 한글임을 확인했다(2026-11-27).
- 배포: https://dongnam-hackathon.magabus.workers.dev/map/ (2026-11-27, workers.dev)
- 정확한 행정경계 필터는 아직 없음. 필요해지면 경계 데이터를 따로 정한다.

## 1-2. 데이터 조사 결과 (2026-11-27)
| 항목 | 결과 | 상태 |
|---|---|---|
| 보행 네트워크(계단·경사 속성) | 부울경용 공공데이터 못 찾음. 서울만 [도보 네트워크](https://data.seoul.go.kr/dataList/OA-21208/S/1/datasetView.do) 있음 | 없음(미확정) |
| 길 뼈대 | OSM 보행로·샛길 부산 약 15,700개 | 사용 가능 |
| 계단 | OSM `highway=steps` 부산 746개(서울 5,415, 울산 146, 창원 195). 보행로 1,000개당 부산 약 47, 서울 약 93 | **희박함** |
| 계단 속성 | 부산 계단 중 경사 방향 23%, 난간 17%, 계단 수 4% | 부족 |
| 고도 | 국토지리정보원 [DEM](https://www.data.go.kr/data/15059920/fileData.do): 제한 없음, IMG, 국토정보플랫폼 로그인 필요, **해상도 미확인** | 확인 필요 |
| 고도 대안 | [Copernicus GLO-30](https://developers.google.com/earth-engine/datasets/catalog/COPERNICUS_DEM_GLO30) 30m, 무료, 출처표기, 건물 높이 포함 | 골목 경사에는 거침 |
| 침수 | [부산 주요도로 침수 정보](https://www.data.go.kr/catalog/15034073/openapi.json) 측정소 14곳, 2018 등록. 침수흔적도는 외부 연계 | 부분적 |

- 계단 태그만 믿으면 계단이 빠진 길을 "계단 없음"으로 안내할 위험이 있다. **경사는 DEM으로 계산해 계단 태그를 보완**한다.
- 집계는 OSM 2026-11-26 한국 추출 파일과 Overpass 결과가 서로 일치했다(부산 746개).

## 1-3. 베이스 지도 검증 (2026-11-27)
- MapLibre GL + OpenFreeMap `positron` 스타일로 부산 일대와 계단 점 2,221개(부울경)를 표시해 동작을 확인했다. 키 없이 로드된다.
- **한글 라벨 적용 완료.** 기본 스타일은 "Busan 부산광역시"처럼 영문이 섞였다. [public/map/index.html](../public/map/index.html)에서 스타일을 받아 이름 라벨을 `name:ko` → `name` 순으로 바꾼다. 부산 화면에서 라벨 15종 모두 한글이었다(영문 0). 번호판(ref)은 그대로다.
- 계단 점은 원도심(서구·동구·중구)에 몰려 있고 다른 지역은 드문 편이다. 빈 동네 분석은 아직 하지 않았다.

## 2. 고정 원칙
1. **지도와 데이터를 분리한다.** 지도는 바탕(타일, 스타일)이고, 코스와 축제는 그 위에 얹는 데이터 레이어다. 새 용도는 레이어 추가로 늘린다.
2. **데이터 형식은 GeoJSON을 기준으로 한다.** 출처가 샘플 파일이든 API든 같은 형식으로 맞춘다.
3. **디자인은 한 곳에서 관리한다.** 색, 둥근 정도, 라벨 규칙은 스타일 파일과 디자인 토큰에 모은다.
4. **가독성이 장식보다 우선이다.** 3D 건물과 효과는 정보 읽기를 방해하면 끈다.
5. **키 없이 시작하고, 필요할 때 바꾼다.** 타일, 검색, 데이터 출처는 설정으로 분리해 교체 가능하게 한다.
6. **요구가 정해지기 전에는 DB, 인증, 서버 기능을 추측해서 만들지 않는다.**

## 3. 구성 요소 (역할 단위)
| 구성 요소 | 역할 | 현재 가정 | 교체 가능성 |
|---|---|---|---|
| 지도 엔진 | 지도를 그리고 조작을 처리 | MapLibre GL JS | 낮음 |
| 타일 | 지도 바탕 데이터 | OpenFreeMap 공개 인스턴스 | 높음 (Protomaps 자체 호스팅 등) |
| 스타일 | 색, 라벨, 건물 표현 | 커스텀 style.json | 계속 수정 |
| 데이터 레이어 | 코스, 축제 같은 내 데이터 | 샘플 GeoJSON | 높음 (공공 API, DB) |
| 위치 | 내 위치와 근처 판단 | 브라우저 위치 정보 | 낮음 |
| 화면(UI) | 상세 카드, 목록, 필터 | 미정 | 높음 |
| 서버 | 정적 서빙, 필요 시 API | Cloudflare Workers | 낮음 |

## 4. 디자인 방향 (큰 틀)
- 파스텔 계열, 큰 둥근 모서리, 부드러운 선 처리
- 정보는 필요한 것만 남기고 POI 라벨은 최소화
- 내 데이터(코스, 축제)가 바탕 지도보다 눈에 띄어야 함
- 색만으로 구분하지 않고, 터치 영역은 넉넉하게
- 구체적인 색과 수치는 구현 단계에서 정하고 한 파일에 기록

## 5. 변경에 대비한 설계 기준
- **새 레이어 추가:** 새 GeoJSON을 등록하면 되고 지도 본체는 수정하지 않는다.
- **데이터 출처 교체:** 같은 GeoJSON을 내놓게 하면 화면은 그대로다.
- **타일 교체:** 스타일 파일의 타일 주소만 바꾼다.
- **서버 도입:** 정적 파일에서 Workers API로 옮겨도 같은 주소 규칙을 쓴다.

## 6. 알려진 위험 (구현 전 확인, 모두 미확인)
- OSM 기반 지도의 부울경 데이터 품질: 계단은 희박함(1-2 참고), 나머지는 미확인
- 한글 라벨: 해결(1-3 참고). 울산·경남 지역은 아직 확인 안 함
- OpenFreeMap 공개 인스턴스의 사용 한도와 안정성 (미확인)
- 정밀 DEM 해상도와 이용 조건 (미확인, 로그인 필요)
- 축제와 러닝코스의 공공 데이터 존재 여부 (미확인)

## 7. 단계 (순서만 고정, 내용은 유동)
1. **기반:** 부울경 범위 지도와 한글 라벨 확인
2. **스타일:** 몽글몽글 디자인 적용
3. **데이터:** 샘플 코스와 축제 표시
4. **상호작용:** 내 위치, 근처, 상세 카드
5. **마무리:** 모바일과 접근성 확인, 기존 검사(`npm run typecheck`, `npm test`, `npm run build`) 통과

각 단계가 끝날 때 방향을 다시 확인하고 변경을 반영한다.

## 8. 완료 판단의 큰 기준
- 부울경 밖으로 벗어나지 않고 한글이 깨지지 않는다.
- 내 데이터 레이어가 바탕 지도 위에서 잘 읽힌다.
- 모바일에서 조작이 된다.
- 기존 검사가 통과한다.

## 9. 열린 항목 (지금 정하지 않아도 됨)
- 데이터는 샘플로 시작할지, 공공 데이터를 조사할지
- 데이터 갱신 방식 (파일 관리 또는 사용자 등록)
- 배포 여부 (배포는 사용자 승인 후 진행)
