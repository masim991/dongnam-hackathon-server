## 범위 해석

해운대 외 기존 상세 데이터를 정리하는 요구와 부울경 전체 산책로를 적재하는 요구는 구분해야 합니다. 부울경 산책로 선형은 유지·추가하고 신호·경사 등 상세 레이어는 해운대 산책로에서 500m 미만으로 제한하는 해석입니다. 삭제 조건을 단순히 `region != 해운대`로 만들면 새 광역 산책로까지 지울 수 있습니다.

‘벡터화’는 지도용 선형/벡터 타일로 해석하며 AI 임베딩·Vectorize와 구분합니다. OSM에서 수집한 후보를 현실의 ‘모든 산책로’로 보증할 수는 없습니다. 수집 시각·영역·태그 조건·실패 지역·완전성 한계를 기록해야 합니다.

500m는 점과 코스 꼭짓점 거리나 중심점 거리가 아니라 코스 선분까지의 최소 거리입니다. 경사 선분은 산책로 선형과의 거리로 평가하고, 경계에서 전체 구간 보존인지 버퍼 안쪽으로 절단인지 명시해야 합니다.

## Android 산출물과 검증

- `android/health-connect`: Health Connect 1.1.0 기반 읽기 전용 라이브러리. 최근 1~7일 삼성헬스 출처 걸음 수·거리 집계, 러닝·트레드밀 세션 페이지 조회, 매 조회 시 권한 확인. 업로드·기록 쓰기·삭제 없음.
- `android/gradlew`, `android/gradlew.bat`, Wrapper와 버전 고정 Gradle 설정 생성 완료. 기존 Node 프로젝트와 별도 빌드입니다.
- 상세 적용법: `docs/android-health-connect.md`. 호스트 Android 앱과 개인정보 처리방침 Activity는 아직 없으며 해당 문서의 Manifest 계약을 실제 앱에서 구현해야 합니다.
- Gradle Wrapper 및 플러그인 설정 성공. Kotlin 조회 기간 검증 테스트 2개는 직접 컴파일·JUnit 실행으로 통과했습니다.
- Android `assembleDebug`, 단위 테스트, lint는 실제 Android SDK 부재로 실행 단계에 진입하지 못했습니다(`SDK location not found`). 전체 모듈 컴파일·AAR 빌드·실기기 연동은 미검증입니다.
- 한글 Windows 경로의 AGP 사전 거부는 이 Android 프로젝트의 `android.overridePathCheck=true`로 처리했습니다. SDK를 설치해도 도구별 한글 경로 호환성은 별도 확인해야 합니다.
- Codex는 변경 내용을 커밋·배포하지 않았습니다. 통합 커밋에서 이 경로를 포함할 때 라이브러리 준비와 출시 완료를 구분해 주세요.

## 진행 중 발견한 장애·검토 사항

### 수정 필요: 날씨 전체 누락을 좋음으로 판정

`src/weather.ts`의 `rate()`는 100점에서 시작해 값이 `null`이면 감점하지 않습니다. 따라서 `rate(observationAt(undefined, undefined))`가 `{score:100, verdict:"good", label:"러닝하기 좋은 날씨", reasons:[]}`를 반환합니다. `weather-api.ts`의 `describe()`는 해당 지역의 `wx[i]`가 없어도 호출되므로 HTTP 200의 빈/부분 응답에서 잘못된 추천이 가능합니다.

Codex가 위 함수를 Node의 TypeScript strip 모드로 직접 실행해 재현했습니다. 담당 파일은 수정하지 않았습니다. Claude 수정 제안: 필수 날씨 필드·관측 시각과 지역별 응답 수를 검증하고, 누락은 `unavailable` 또는 502/부분 실패로 표시합니다. 그 지역을 추천 시간대와 유효 날씨 집계에서 제외하고 누락 회귀 검사를 추가해 주세요.

- Claude 화면에서 D1 일일 쓰기 한도가 소진되어 삭제·정밀화 적재를 보류하고 날씨 API·정적 벡터·Android 설정을 진행한다는 보고를 확인했습니다. Codex가 D1에서 직접 확인한 수치는 아닙니다.
- D1 무료 일일 쿼터는 UTC 자정(한국 09:00)에 초기화됩니다. 실제 플랜·오류를 먼저 확인하고, 한도 상태에서 삭제 재시도나 반복 전체 적재를 하지 않는 편이 좋습니다. 유료 전환은 별도 비용 결정입니다. 근거: https://developers.cloudflare.com/d1/platform/pricing/
- 날씨 API는 누락·오래된 데이터·공급자 오류를 ‘러닝하기 좋음’으로 처리하면 안 됩니다. 풍향은 359°와 1°를 산술 평균하면 180°가 되는 순환각 문제를 처리하고, 방향 단독으로 좋고 나쁨을 판단하지 않습니다.
- 바람 단위(m/s와 km/h), 기온·습도의 관측 시각, 강수·돌풍을 명시해야 합니다. 러닝 지수는 서비스의 임시 기준임을 표시하고 의학적으로 검증된 안전 판정이라고 설명하지 않습니다.
- `grade10`처럼 경사 10% 이상만 있는 데이터로 전체 코스 평균 경사나 누적 상승고도를 계산하지 않습니다. DEM 해상도·이상치·출처 기준일의 한계도 함께 기록합니다.
